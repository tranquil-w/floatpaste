# Win+V 接管走注册表释放路线

系统 Win+V 被 TextInputHost.exe 抢先注册，普通进程 RegisterHotKey 必然失败（1409），无法直接覆盖。决定提供「接管 Win+V」一键开关：警告后写注册表 `HKCU\...\Explorer\Advanced\DisabledHotkeys` 释放该组合，注销/重启后自动注册，关闭开关即恢复原热键并清除注册表值，全程可逆。

## Considered Options

- **低级键盘钩子（WH_KEYBOARD_LL）硬拦**：拒绝。前台为高完整性进程时收不到按键（与管理员上屏能力冲突）、响应过慢会被系统摘钩、与其他钩子类工具互斥。
- **仅注册失败提示、不提供接管**：拒绝。用户明确要求一键开启（含副作用警告与可回退）。

## Consequences

- 生效与回退各需一次 Explorer 重启，且是两次独立重启（2026-09-19 晚补充实测）：开启后重启一次释放系统组合（本次实验同时让系统持有方永久放弃该组合）；关闭开关后**再**重启一次，系统持有方才重新接管。只关开关不重启 = Win+V 空悬无人响应（重启电脑可自愈）。关闭开关时将「重启资源管理器恢复系统」按钮直接置两段式确认态高亮，把这一步变成不可漏的引导。
- 系统持有方不是 TextInputHost.exe（kill 它无效，会自动重拉但不注册）；持有方随 Explorer 启动链拉起，干净状态下（无 V 值、无人占用）重启 Explorer 即重新持有（RegisterHotKey 探测 1409 复现）。
- 系统剪贴板历史**保持开启**亦可成功释放并注册 Win+V（同机同轮实测，`EnableClipboardHistory=1`），接管向导无需引导用户关闭系统历史。
- 生效与回退的收尾动作由 `TaskbarCreated` 广播驱动（explorer 重启的官方信号，托盘已监听）：接管开启时延迟补注册（广播早于系统释放热键完成），接管关闭时解除「待重启恢复」过渡提示。用户经按钮重启、手动重启或重启开机均覆盖，无需重启本应用。
- Win+V 固定绑定为速贴唤起的第二个入口（与主快捷键同动作），不独立可配置；设置页将其紧随「速贴唤起」行呈现。用户把主/搜索快捷键录成 Win 组合时按接管开关状态给出指引，与自身快捷键的冲突和系统占用（1409）用不同状态码区分，提示不混用。
- 卸载必须清理注册表残留：卸载器从 `DisabledHotkeys` 移除 V（其他字母保留、删空整值删除）并提示重启 Explorer，否则系统 Win+V 在卸载后永久失效。
- 调研依据：RegisterHotKey 官方文档（Win 组合保留声明）、CopyQ #1668/#2422、Ditto #143、本仓库 2026-09-19 真机 spike（`.artifacts/winv-spike/`）。
