# 测试体系

自动化测试分三层，各层只覆盖自己擅长的不稳定面，不越层重复：

| 层 | 位置 | 覆盖目标 |
|----|------|----------|
| 单元 | 各模块 `#[cfg(test)]` | 纯函数与算法边界、错误路径、序列化兼容、平台二进制契约 |
| L1 进程内集成 | `floatpaste-core/tests/` | 临时库组装 `CoreState`，沿公共 API 串行验证连贯业务流（录入→去重→标签→收藏→搜索→软删→保留清理） |
| L2 无头 UI 驱动 | `floatpaste-native` 内联测试 | `set_size` + `dispatch_event` 驱动 Slint 窗口断言 UI 行为；winit 事件循环是进程级单例，此类测试必须单函数串行多段 |
| L3 真进程 E2E | `floatpaste-native/tests/e2e_smoke.rs` | spawn 真实二进制走完整用户链路，覆盖主要工作流；断言隔离库、窗口几何与前台归属 |

层间分工原则：**主要工作流以 L3 兜底**（录入、去重、图片、保留清理、面板开关、监听切换、搜索开窗、收藏、两段式删除），单元测试只保留 e2e 不可达的部分——纯函数边界、渲染/布局管线（L2）、持久化格式兼容、FTS 语义、UIA 插符解析等平台契约。与 e2e 重复的端到端行为断言不写在单测里。

运行入口统一为 `cargo test`（含全部层）；单跑 L3 用
`cargo test -p floatpaste-native --test e2e_smoke`。

## L2 无头驱动约束

- 入口唯一：各窗口契约段以 `pub(crate) fn run()` 提供并由单一 `#[test]`
  （`l2_headless_ui_contracts`）串行调用——Slint 平台绑定首个初始化它的
  线程，`#[test]` 各占一线程，多入口会抢占线程绑定而实例化失败
- 布局读数须在事件循环泵帧后取：无循环时布局 pass 不跑，行模型注入后
  `content-height` 等布局派生属性停留在旧值；不受布局影响的属性
  （如 Flickable 偏移）可直接赋值断言
- `changed` 回调由事件循环调度而非属性赋值时同步执行：断言其副作用须
  先泵一次循环（`run_event_loop_until_quit` + 定时线程 `quit_event_loop`，
  异步落地（`invoke_from_event_loop` 的闭包）同样只有循环运行时才消费）
- 查询链路用临时 SQLite 直写预置数据，不经系统剪贴板（互斥资源，
  见 L3 约束）

## L3 端到端约束

### 隔离

被测实例的全部状态必须圈在临时目录内，靠以下钩子实现（缺省会走生产行为，钩子仅测试使用）：

- `APPDATA=<临时目录>`：进程级环境变量重定向，数据库、图片存储、日志随之整体隔离
- `FLOATPASTE_INSTANCE_ID`（仅字母数字与连字符）：给单实例互斥量与唤醒事件名追加后缀，被测实例与日常实例共存
- `FLOATPASTE_RETENTION_FIRST_DELAY_MS`：覆盖保留清理首轮延迟（默认 60s），让接线验证落在测试时间尺度
- `FLOATPASTE_SKIP_AUTOSTART_SYNC=1`：跳过自启同步——它操作真实系统的 Run 键与任务计划，不随 APPDATA 隔离
- `FLOATPASTE_E2E_KEEP=1`（诊断用）：保留临时目录（实例日志在 `com.floatpaste/logs`），供间歇失败的事后取证；默认清理

### 驱动与断言

- 外部驱动只走真实用户路径：写系统剪贴板触发录入、二次启动进程经唤醒事件开关速贴面板；不使用键盘注入（SendInput 在安全软件环境不可靠），上屏注入环节留给人工验收
- 托盘菜单命令与键盘动作经命名事件驱动（模态菜单点击、按键注入均无法可靠自动化；事件触发的处理路径与真实入口的终点相同，仅绕过分发层；均仅 `FLOATPASTE_INSTANCE_ID` 设置时装载）：
  - `signal_test_toggle_monitoring` — 托盘「切换监听」
  - `signal_test_open_search` — 托盘「打开搜索」
  - `signal_test_search_escape` — 搜索窗 Esc 关闭（key-close 回调）
  - `signal_test_picker_favorite` — 速贴收藏切换（toggle_favorite）
  - `signal_test_search_delete` — 搜索窗两段式删除（request_delete）
- 键盘动作的到达前提是会话活跃（与真实按键的 FocusScope 前提对齐），驱动前须确认对应窗口已激活
- 速贴面板显隐是「屏内 ↔ 屏外停屏（-32000 平移）」语义而非 `SW_HIDE`，`IsWindowVisible` 恒真——面板开合断言必须看窗口几何（`GetWindowRect` 左上角是否在屏内）
- 键盘动作前等数据落地：窗口落位先于异步列表加载（fetch_next），此时行缓存为空、动作会静默返回；**高度收缩到结果高度 = 数据已入库渲染**，以此作为几何侧的就绪信号
- 两段式删除的两次触发必须都落在待确认窗口（3s）内且期间无选中变化（选中切换会解除待确认态）
- 速贴定位预置 `LastPosition` 模式与屏内记忆位置：Mouse/Caret 模式依赖运行环境的光标与前台窗口，E2E 验证的是唤醒链路而非定位模式
- 搜索窗几何断言（顶边锚定）用独立第二实例：矮数据集保证「起步满高 → 落地收缩」必然发生；顶边基准用与被测实例同源的 `center_in_work_area` 复算「满高起步的居中 top」——直接对比窗口两次读数会在首读已收缩完成时漏检重居中回归；光标读取被拒（输入桌面不可达）时与应用同样退回主屏工作区复算基准，单屏下逐位一致；双实例并存时存在同标题停屏搜索窗，且 winit 预建的隐藏窗口自进程启动起就停在级联默认位——枚举必须按「屏内 + `IsWindowVisible`」过滤，否则会赛跑赢过应用自身的装配落位
- 前台归属断言（Esc 还原）依赖「打开时前台是确定目标」：测试进程创建真实顶层窗口并以 `AttachThreadInput` 手法取得前台（复用被测实例同款 `force_foreground_window`）；**目标窗口的消息必须被泵出**（前台转移经跨线程消息往返异步落地，忙轮询不泵消息会让激活永不落地、随后被停屏清空成 NULL 前台）——轮询闭包内对目标窗口执行消息泵；无人值守会话（无交互前台，`GetForegroundWindow` 为空）拿不到则焦点段整段跳过——焦点语义只能在交互桌面验证

### 卫生纪律

- 单测试函数串行推进：系统剪贴板、全局热键、速贴窗口都是会话级全局资源
- 子进程回收必须用 Drop 守卫覆盖 panic unwind 路径：孤儿被测实例持有外层管道句柄会把整条测试命令挂死
- 被测实例收尾走优雅退出（`signal_test_exit` 命名事件 → 正常收尾路径），超时才兜底强杀：进程在剪贴板打开临界区内死亡会把系统剪贴板锁死（见下方故障模式），且死进程的剪贴板数据句柄随之失效、污染后续所有进程的读取
- 剪贴板是互斥资源，输入法、剪贴板管理器等外部进程会间歇占用，写入类操作短重试，持续失败让测试失败（不掩盖环境故障）
- 预置数据的活动时间戳以 1ms 步进保证严格单调：排序并列时（同毫秒入库）「最新条目」的选中/删除目标不确定
- 运行副作用：被测实例短暂占用主/搜索快捷键组合、读写系统剪贴板（结束时尽力恢复原文本）

### 环境坏态与失败模式

L3 的间歇失败绝大多数是**环境坏态**而非代码回归。已知形态：

- **系统剪贴板锁死**：`OpenClipboard` 持续 `ERROR_ACCESS_DENIED`（成因见下节）——测试前置探测跳过
- **剪贴板死句柄**：剪贴板里存在已失效进程遗留的 `CF_HDROP` 数据，读侧报「句柄无效」——实例启动核对会重试数轮后放弃（八百毫秒间隔 × 10 次），期间不影响后续监听；这是「某进程死在剪贴板临界区」的化石证据，重启 explorer 清除
- **无交互前台**：`GetForegroundWindow()` 恒为 NULL（无人值守/断连会话）——焦点还原断言整段跳过属预期，不要当回归修
- **explorer 刚重启**：shell 组件冷启动期剪贴板长持有高发，前几轮测试易撞上；等几分钟或先跑一次让组件进入稳态

间歇失败的责任判定手段：`FLOATPASTE_E2E_KEEP=1` 保留现场日志 →
读被测实例日志（激励到达时刻 vs 断言超时）；`git stash` 后用 HEAD
基线复跑对照——基线同样复现即环境问题。

### 故障模式：系统剪贴板锁死

系统剪贴板是全局互斥资源，锁死后 `OpenClipboard` 持续返回
`ERROR_ACCESS_DENIED`，无法自愈。两种成因，恢复手段相同：

- 外部进程打开剪贴板后持有不释放（实测：shell 组件——explorer 树内的
  TextInputHost/WebView2 组件群会周期性进入此态，锁死瞬间无进程死亡、
  `GetOpenClipboardWindow` 查无持有者，杀 explorer 树 1 秒内释放）
- 任意进程在剪贴板打开临界区内死亡（强杀、崩溃——受控实验已实证）

恢复手段：重启 explorer（`taskkill /f /im explorer.exe && start
explorer.exe`，连带退出坏态 shell 组件并拉起新实例）或注销重登。

测试对此分两段处理：

- 启动前探测（`clipboard_unusable_before_start`）：~1.2 秒内无法打开即
  视为环境先在的锁死/长占用态——此时测试与被测实例都还没碰过剪贴板，
  责任不在被测物，打印恢复指引后跳过，不把环境故障计成测试失败
- 运行中途失败仍照常报错：写入短重试后 panic，附带锁死恢复指引——
  中途失效可能是被测实例把剪贴板搞坏，不得跳过掩盖

多测试目标全量并行时为低概率竞态，单跑 E2E 稳定。
